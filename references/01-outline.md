# 标题识别

## 为什么要先找"编号体系"而不是逐段猜

逐段打分最容易在两个地方翻车：

- **假阳性**：`案例1：analemma / 日行迹`。它短、加粗、以数字编号开头——单看形状像三级标题。
  但它的序号是跨章节的平坦序列（1…27），不符合"子级在父级下重新计数"的层级结构，
  而且后面紧跟大段正文。序列一致性检查能把它自动排掉。
- **假阴性**：`《太阳》第一章 Sacred Sun`（附录里的小标题）。没有可识别的编号，字号也和正文一样。
  这种只能靠人工在"候选"里提级——所以候选必须列出来，不能因为判为正文就不显示。

## 序列一致性的两个坑

1. **目录域会把序列搅乱。** 目录里也有"第一章、第二章…"，和正文的合在一起就变成
   1,2,3,4,1,2,3,4。所以要先用 TOC 样式名 + `fldChar` 区间把目录段标出来排除。
2. **平级不是重启。** 判断"是否重启过"时条件必须是 `b < a and b == 1`，写成 `b <= a` 会把
   `1.1, 1.2` 这种同章内的平级也算成重启，导致 `dotted2` 被误判为不成体系。

## 兜底信号什么时候才用

文档里已经有成体系的编号时（`strong=True`），**关掉**"短行+加粗+居中"这类兜底打分。
否则封面上的"某某大学""硕士学位论文"会被判成二级标题。
没有任何编号体系时才启用兜底，阈值 0.65。

## 强制拦截

`apply` 读 `02_outline.tsv`，找不到 `# CONFIRMED: yes` 就 `sys.exit`。
理由：标题层级错了，目录、页眉、分页、页码全跟着错，而且错得不显眼。
宁可多问一次，不要产出一份看起来没问题的错文件。

## audit 反过来能查出 outline 的漏判

`audit` 报「正文存在非规定字号」时，先别急着改格式——**多半是 outline 漏判了标题**。
漏判的标题留在正文里，还带着草稿里的大字号，就会出现在这个分布里。
例：附录下的小标题 `《太阳》第一章 Sacred Sun` 没被提级，27 个 run 是小三号，
audit 就报 `{'24': 4994, '30': 27}`。回到 `02_outline.tsv` 把它们改成 `2` 再 apply 即可。

apply 只归一段落属性（行距、缩进、对齐），**不动 run 的字体字号**——否则会把引文块、
加粗标签这些有意的排版一起抹平。字号异常交给 audit 报，由人判断。
